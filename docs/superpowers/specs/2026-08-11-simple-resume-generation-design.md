# 低门槛简历生成与优化

## 目标

让没有简历的新手和已有简历的用户都能在极少步骤内获得可编辑、可导出的中文简历；不要求填写职位 JD。

## 用户流程

首页点击“开始做简历”后，只出现两个选择：

1. **我有简历，帮我优化**：上传 PDF/DOCX/TXT 或粘贴文本；可选填写求职方向；点击生成后得到优化稿和逐条改动对比。
2. **我是小白，从零开始**：在同一页填写“想找什么工作”和“做过什么”。后者接受自由文本，并提示课程项目、社团、兼职、实习和技能均可填写；点击生成后得到首版简历。

两条路径均进入同一编辑和导出页。后续补充信息为成稿页的可选建议，不能阻塞导出。

## 生成与优化原则

- 求职方向仅用于调整表达重点和简历标题；不要求职位 JD、公司名称或关键词。
- 已有简历优化必须保留事实和章节，不得虚构数字、工具、职位或经历；保留原文件预览并提供可验证改动列表。
- 从零生成只将用户提供的课程、项目、活动、兼职和技能转换为简历结构；缺失事实留空或不展示，不能编造。
- 任何没有可安全改写的情况均要给出可操作原因及下一步，而不是笼统提示“没找到可优化内容”。

## 交互边界

- 首屏不展示评分、JD、长问卷、模型名称或复杂诊断。
- 生成前仅阻止空的关键输入：优化路径需要可读简历；从零路径需要岗位方向和至少一条经历描述。
- 生成后可选显示一条补充建议，例如“补充项目目标或结果，可进一步增强表达”。

## 复用策略与许可证

- 直接复用或改写 **Reactive Resume（MIT）** 中适配当前架构的结构化简历编辑、章节模型和安全 JSON Patch 思路。
- 不复制 **OpenResume**、**ResumeLM** 等 AGPL 项目的代码；仅参考公开的交互思路，避免将 AGPL 义务引入本站。
- 所有复用代码需保留原许可证和归属声明，并以当前 React/Vite/Express 架构实现。

## 验收

- 新手能在一个页面完成岗位与经历输入，生成首版简历并导出。
- 已有简历用户无需 JD，能完成方向可选的优化。
- 两条路径都不会因“没有足够改写”而只给笼统失败提示。
- 自动化测试覆盖两条请求契约、缺失信息提示、事实安全和编辑页数据映射。
