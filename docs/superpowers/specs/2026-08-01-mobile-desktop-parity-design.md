# 手机端与电脑端能力一致性设计

日期：2026-08-01

## 目标

让 360px～430px 宽度的手机用户获得与电脑端完全一致的核心能力和结果质量。手机端不是精简版：上传已有简历、从零生成简历、岗位分析、追问补充、DeepSeek 优化、质量审核、编辑预览、保存版本、历史恢复和导出均复用电脑端的同一套状态、服务与质量门槛。

本次只调整响应式布局、信息层级和触摸交互，不创建独立的移动端业务流程，也不改变已经验证的 AI 优化逻辑。

## 方案选择

### 方案一：继续追加零散媒体查询

改动较小，但当前样式已经存在多个相互重叠的断点，继续补丁式修改会增加覆盖冲突，难以稳定保证所有页面的手机体验。

### 方案二：共享业务逻辑，建立统一的移动端呈现体系（采用）

保留现有 React 状态流、接口调用、生成流程和质量审核，仅统一响应式断点、移动端容器、步骤导航、编辑/预览切换和底部操作区。这样能同时保证结果一致性和长期可维护性。

### 方案三：单独建立手机端组件树

可以获得最大的布局自由，但会形成两套流程，容易在后续更新中出现手机端与电脑端逻辑和结果不同步，因此不采用。

## 架构与数据流

- `App.tsx` 继续作为唯一流程状态源，手机端与电脑端读取同一份简历、岗位、追问、生成结果、质量报告和版本记录。
- `resumeAnalyzer`、`creatorResume`、`aiOptimize`、质量审核与存储服务保持单一入口，不增加移动端专用参数或降级逻辑。
- 页面组件继续共用；仅在组件内部根据布局需要改变排列、显隐方式和交互载体。
- 所有提交动作保持同一个处理函数，避免桌面按钮和手机按钮执行不同逻辑。
- 切换编辑/预览或页面步骤时保留输入状态，不重新初始化或丢失 AI 结果。

## 手机端交互设计

### 全局框架与步骤导航

- 顶部导航压缩为清晰的品牌、当前步骤和必要入口。
- 工作流步骤在手机上显示当前步骤名称及进度，例如“第 3/5 步”，不只保留难以理解的图标。
- 页面内容使用统一左右边距和安全区，避免贴边、横向滚动与固定元素遮挡。
- 成功、警告和错误提示限制在可视宽度内，并避开刘海和浏览器顶部区域。

### 首页与入口

- 保留“上传已有简历”和“从零写简历”两个同等级入口。
- 主按钮在窄屏下纵向排列且占满可用宽度，触摸区域不少于 44px。
- 首页内容保持精简，但不能隐藏影响用户选择流程的重要说明。

### 已有简历优化流程

- 上传、粘贴、填写岗位信息、分析、补充追问、生成和质量审核与电脑端完全一致。
- 编辑区和原文/效果预览使用明确的标签切换；切换只改变视图，不改变数据。
- 生成中的状态、失败重试和质量门槛完整呈现，防止重复提交。

### 从零生成简历流程

- 创作表单改为单列，字段标签、示例和帮助文字保持完整。
- 教育、经历、项目、技能和求职方向的新增、删除、排序操作适配触摸。
- 输入控件字号不低于 16px，避免移动浏览器聚焦时自动放大。
- 生成后进入与已有简历相同的质量审核、编辑、保存和导出流程。

### 报告、追问与生成

- 分析卡片纵向排列，核心优势、缺口和建议不因屏幕较小而被裁剪或减少。
- 一次突出当前问题，返回、跳过和继续操作始终可见。
- AI 生成进度、质量审核结果以及需要补充的信息均完整显示。

### 编辑、预览、版本与导出

- 编辑和预览在手机端使用标签切换，桌面端继续使用适合大屏的布局。
- 简历纸张预览按视口缩放，不使用导致横向溢出的固定最小宽度。
- 保存、重新生成和导出放入安全区感知的底部操作栏；操作栏不得遮挡正文和输入框。
- 历史版本以单列卡片显示，恢复按钮全宽或具备足够点击面积。

## 响应式与样式策略

- 以内容需求统一断点：手机、小型桌面/平板、完整桌面，清理或收敛相互冲突的旧媒体查询。
- 使用 CSS 变量统一页面边距、控件高度、底部操作栏高度和 `env(safe-area-inset-*)`。
- 手机端所有主要交互目标至少 44px；正文和表单保持可读字号和行高。
- 固定/粘性元素必须为正文预留空间，并在软键盘出现时保持关键操作可访问。
- 不依赖仅悬停才能发现的操作，触屏设备始终提供可见入口。

## 错误处理与状态保护

- 接口失败、文件解析失败、AI 失败和导出失败使用一致的可恢复提示。
- 生成期间禁用重复提交，但允许用户看见明确进度。
- 页面切换和编辑/预览切换不得丢失未保存输入。
- 预览或导出失败不得覆盖已有的成功版本。

## 验收标准

在 360×800、390×844、430×932 以及 1440px 桌面视口逐项验证：

1. 页面无非预期横向滚动、裁剪、按钮重叠或固定栏遮挡。
2. 从首页到编辑器完整跑通“上传已有简历”流程。
3. 从首页到编辑器完整跑通“从零生成简历”流程。
4. 两种视口调用相同的 AI、质量审核、存储和导出服务，结果字段和质量门槛一致。
5. 表单输入、增删经历、步骤返回、失败重试、编辑/预览切换均不丢状态。
6. 保存版本、历史恢复、重新生成和导出在手机端均可完成。
7. 浏览器控制台无新增错误，现有自动化测试全部通过。
8. 部署后验证 `https://znhil.xyz` 的桌面端和手机端；不得修改或影响 `http://218.244.153.12/` 与 `http://218.244.153.12/leka-showcase/`。

## 非目标

- 不更换已确认的 DeepSeek 正式模型。
- 不降低或重写现有简历生成与优化质量规则。
- 不创建独立移动端后端、数据库或部署目录。
- 不修改同一服务器上的其他网站、反向代理、数据库或容器。
