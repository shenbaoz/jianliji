# DeepSeek V4 Flash 强简历优化设计

## 目标

将生产环境的 DeepSeek 主模型从已弃用的 `deepseek-chat` 升级为官方当前模型 `deepseek-v4-flash`，并让优化结果相比原简历有明显的结构与表达提升，同时避免未经确认的虚假经历直接进入可投递版本。

## 模型与降级策略

- 主模型：DeepSeek 官方 OpenAI 兼容接口 `https://api.deepseek.com/chat/completions`，模型 `deepseek-v4-flash`。
- 备用模型：保留现有 Kimi，仅在 DeepSeek 出现超时、限流或临时服务错误时启用。
- 不再使用已弃用的 `deepseek-chat` 或 `deepseek-reasoner` 模型名。
- API 密钥只保存在服务器环境变量中，前端不得获得或输出密钥。

## 一键三阶段优化

一次用户操作在服务端自动完成三个阶段，用户不需要重复点击或反复修改提示词：

1. **岗位策略分析**：读取目标岗位、JD、原简历和补充证据，确定岗位关键词、经历优先级、删除项和推荐结构。
2. **强力度重写**：依据岗位策略生成明显区别于原文的投递版简历，重排内容并重写要点，而不是原句润色。
3. **招聘经理质检与定稿**：再次检查岗位匹配、事实边界、表达力度、重复内容、篇幅和可读性，自动修正后只向用户返回最终成品。

三个阶段默认都使用 `deepseek-v4-flash`。任何阶段出现临时故障时，服务端可以重试；只有 DeepSeek 整体不可用时才启用 Kimi 备用。中间分析和草稿不展示给用户，也不写入版本数据库。

## 强优化规则

AI 输出必须明显区别于原文，重点完成：

1. 根据目标岗位与 JD 重新排序经历和技能。
2. 把职责描述改写成“动作 + 场景/方法 + 结果”的专业要点。
3. 合并重复内容，删除空泛、自我评价式和弱相关描述。
4. 保留用户已经提供的公司、职位、项目、工具和数字，不改变事实含义。
5. 原文没有成果数据时，最终成品使用不依赖虚假数字的专业表达；可以另外提出合理的成果方向，但必须以 `[待确认]` 标记，不能冒充已发生事实。
6. `[待确认]` 建议放在独立的可选改进区，不混入最终简历正文，也不阻止用户保存和导出已经完成的成品。
7. 最终正文必须达到最低变化幅度，不能只是替换少量词语或返回接近原文的内容。

## 用户流程

用户导入简历并填写目标岗位/JD后，只需执行一次优化操作。系统可以使用用户已经填写的证据，但不得把补充回答设为生成成品的必经阻塞步骤。结果页分为两类内容：

- 可直接使用：仅基于原简历和用户回答完成的重写。
- 待确认建议：模型推导出的成果方向或缺失证据问题，使用清晰标记提示用户确认或删除。

补充问题只作为可选增强项，不要求用户为获得第一版成品而反复回答。如果 AI 服务不可用，页面必须明确提示正在使用本地规则草稿，不能让用户误以为已完成 AI 强优化。

## 成品质检门槛

第三阶段必须在返回结果前检查：

- 核心经历是否按目标岗位的重要性排序。
- 是否覆盖 JD 中与用户证据相符的关键要求。
- 是否存在重复要点、空泛自评、半句话、模板话或无关经历。
- 是否新增了原文和用户回答中没有的公司、职位、项目、工具或具体数字。
- 优化文本与原文是否存在足够明显的结构和表达差异。
- 是否保持适合招聘者快速阅读的一页式信息密度。

未达到门槛时，服务端在同一次用户操作内自动返修一次；用户不需要再次点击“优化”。

## 接口与数据边界

- 保持现有 `/api/ai/optimize` 路由和前端调用方式，减少部署风险。
- 服务端继续对姓名、手机号、邮箱、身份证和详细地址进行脱敏。
- 服务端内部传递岗位策略、草稿和质检反馈，最终只返回 `provider`、`model`、定稿文本、可选待确认建议和质检结果。
- 继续限制请求长度、调用频率和超时时间。

## 测试与验收

- 单元测试确认三个阶段均请求 `deepseek-v4-flash`，且不再出现 `deepseek-chat`。
- 流程测试确认一次前端操作会自动完成策略、重写和质检定稿，不要求用户重复触发。
- 提示词测试确认允许强重写，但禁止虚构公司、职位、项目、工具及具体数字。
- 行为测试确认弱原文会得到明显不同的岗位化结果。
- 安全测试确认新增数字或工具仍会触发质检标记。
- 导出测试确认 `[待确认]` 建议与正式简历正文分离，正式正文可以直接导出。
- 完整构建和全部自动化测试通过后，部署到 `znhil.xyz` 的独立目录和容器。
- 线上验收包含 AI 实际调用、移动端结果展示、API 健康检查，以及两个受保护旧站的状态与内容字节数回归。

## 不在本次范围

- 不修改数据库结构。
- 不改变旧 IP 主站或 `/leka-showcase/`。
- 不新增付费、登录或账号系统。
- 不生成可冒充真实事实的虚假工作经历或量化业绩。
