# 通用投递简历设计

## 目标

让用户一次生成一份可投递多个相近岗位的真实简历，而不是为每家公司重复填写 JD 或完成追问。

## 用户主流程

1. 上传、粘贴已有简历；小白用户填写基础资料、教育、项目与技能。
2. 用户填写一个求职方向，例如“内容运营、新媒体运营”。
3. AI 依据该方向的共同能力要求，在不虚构经历、数据或技能的前提下直接生成可编辑简历。
4. 用户保存、导出并投递多个相近岗位。

JD 不在默认流程中出现。未来如需针对某个特殊岗位调整，应作为成稿后的独立可选功能，不影响默认生成。

## 有效优化规则

- 只使用用户提供的真实经历和技能作为证据。
- 让经历表达清楚职责、行动和已有结果；没有结果时保留真实描述，不编造量化数据。
- 围绕用户填写的求职方向提炼该类岗位通用的关键词、技能顺序和经历优先级。
- 删除或弱化与该方向无关、重复或空泛的表述。
- 不展示虚假分数、营销式“提升”或要求用户完成补证据问答。

## 界面原则

- 普通优化：简历原稿、求职方向、生成简历，三步完成。
- 小白生成：保留必要的资料填写，但把岗位 JD 改成只需填写“求职方向”；完成资料后直接生成。
- 成稿页将重点放在编辑、保存和导出，不把诊断、补问题或单公司 JD 放回主流程。

## 验收

- 用户可仅凭简历和自填求职方向获得成稿。
- 主流程没有必填 JD、补证据问题或匹配分数。
- 小白生成和已有简历优化使用相同的“求职方向”规则。
- 生成结果继续经过现有真实性和联系方式脱敏保护。
