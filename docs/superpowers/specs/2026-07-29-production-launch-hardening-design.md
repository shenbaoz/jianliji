# 简历记生产上线收口设计

## 目标

把当前“简历记”从可演示版本收口为可公开部署版本。最终版本必须保护简历隐私、限制匿名接口成本和容量、让管理台展示真实全站数据，并通过两份真实中文简历的完整求职流程验收。

## 范围

- 保留 React 19、Vite、Express 5 和 MySQL 的现有架构。
- 修复上传文件匿名访问、文件类型绕过、AI 出站脱敏不完整和云端数据删除不完整。
- 为 AI 请求增加专用限流、超时、载荷边界和已有备用模型回退。
- 让管理员通过受保护接口读取和删除全站简历版本，普通访客接口继续只访问自己的数据。
- 限制每位访客保留的简历版本数量，并清理被淘汰版本关联的临时文件。
- 修复 PDF 文本换行造成的残句、姓名识别失败、岗位职责标题误判、已存在证据漏判和不真实的修改前后对比。
- 修复案例库“全部/运营”筛选和空状态，完善移动端主操作区。
- 把 DOCX、PDF、导出和其他非首屏重模块改为按功能触发加载。
- 补全生产安全响应头、环境变量说明、Nginx 配置、健康检查和回滚验证。

## 非目标

- 不在本轮增加账号、支付、会员或社交登录。
- 不重写整个分析器或更换前后端框架。
- 不把管理密码、数据库密码或模型密钥写入前端、日志、仓库或构建产物。
- 不修改服务器根站和 `/leka-showcase/` 的文件、Nginx location、上游或进程。
- 不覆盖工作区中与本轮无关的用户未提交改动。

## 架构与数据边界

### 上传和文件访问

上传入口只接受 PDF、DOCX 和纯文本。服务端必须根据文件签名与结构判断真实类型，不能信任文件名、扩展名或浏览器 MIME。文件使用服务端生成的随机名称保存，不提供匿名静态目录；需要预览或下载时，通过带访客所有权校验的 API 流式返回，并设置 `Cache-Control: no-store`、`Content-Disposition` 和 `X-Content-Type-Options: nosniff`。解析失败、用户删除、版本淘汰和过期清理都要删除关联文件。

### AI 隐私和成本控制

所有发送给 DeepSeek 或 Kimi 的内容必须先经过同一个出站脱敏函数，包括原简历、岗位描述、补充回答和重试载荷。脱敏至少覆盖手机号、邮箱、身份证号、详细地址和可确定的候选人姓名；学校、公司和项目经历默认保留，因为它们是岗位匹配证据，但隐私页必须准确披露这一点。

AI 路由使用比通用接口更严格的独立限流、最大请求体、请求超时和并发边界。DeepSeek 出现超时或临时 5xx 时使用现有 Kimi 备用；两个模型均失败时返回可识别的服务错误，由前端明确提示并允许生成经过真实性约束的本地安全初稿。

### 版本和管理台

普通版本接口继续通过访客标识隔离。新增或修正的管理员版本接口必须先验证 HttpOnly 管理会话，再在服务端执行全站查询、统计、导出和删除，不能复用浏览器访客标识。每位访客只保留最近的有限数量版本；写入新版本后，在同一数据层清理超额记录。

管理员 Cookie 在开发环境使用 `/`，生产部署在 `/resume-fit/` 时使用 `/resume-fit/`，并根据 HTTPS 设置 `Secure`。生产环境未设置强管理密码或 MySQL 不可用时，服务拒绝启动。

## 简历质量

PDF/DOCX 文本进入分析器前先做结构化规范化：连接被 PDF 换行拆开的中文短语，保留真实段落边界，删除重复页眉页脚和不可见控制字符。姓名识别优先使用简历顶部短行，并排除电话、邮箱、学校、公司和章节标题。

岗位要求提取只处理任职要求、资格条件和明确门槛，不把“岗位职责”等标题本身当作要求。匹配判定使用规范化后的简历证据，已有技能、项目和量化结果不能漏判。生成后的每一条经历必须是完整句，不得出现“负责理…”等截断残句；新增数字、工具和业绩继续受真实性审计约束。

“优化了哪里”只能展示真实对应的改写或重排。无法建立语义对应关系的两行不得强行配对。

## 前端体验和性能

案例库的“全部”返回全部案例，分类筛选按真实分类值工作；无结果时显示明确空状态和恢复入口。移动端主操作改为不换行或纵向全宽布局，保证 390 像素视口无水平滚动。

首屏不预加载 DOCX 编辑、PDF 处理、导出和管理台模块。重模块通过动态导入在用户进入对应功能时加载，并显示现有风格的加载状态；不做与真实包体收益无关的组件重构。

隐私页文案与真实行为一致，明确说明发送给第三方模型的字段、保存位置、保留期限和删除方式。提供删除当前访客云端版本及关联文件的入口。

## 错误处理和安全响应头

客户端可修正的上传错误返回 4xx 和可操作文案；未预期异常只向用户返回通用信息，详细堆栈仅留在服务器日志。生产 Nginx 或 Express 添加 CSP、HSTS（仅 HTTPS）、`frame-ancestors`、Referrer-Policy、Permissions-Policy 和 `nosniff`，同时保证 PDF/DOCX 下载正常。

健康接口只公开必要状态，不泄露密钥、数据库地址或内部路径；受保护的管理健康信息可显示数据库和模型配置是否就绪。

## 验证

1. 每项行为修复先增加会失败的回归测试，再做最小实现。
2. 运行完整 Node 测试、TypeScript 检查、Vite 生产构建和生产依赖审计。
3. 使用两份真实 PDF 分别完成导入、岗位分析、追问、生成、编辑、保存版本、重新打开和导出。
4. 验证 DeepSeek 正常、超时/5xx 回退和双模型失败三条路径。
5. 在桌面和 390×844 视口验证首页、导入、案例库、创建器、编辑器和隐私删除流程，无控制台错误和水平滚动。
6. 使用管理员会话验证全站统计、版本读取和删除；验证普通访客无法访问管理数据。
7. 以生产环境变量启动服务，确认 Node 仅监听回环地址，`/resume-fit/` 和 `/resume-fit/api/health` 正常。
8. 部署时仅新增或更新 `/resume-fit/` 的静态目录、反向代理和独立进程；部署后再次确认根站和 `/leka-showcase/` 的响应未变化。

## 完成标准

- 所有自动化测试、生产构建和依赖审计通过。
- 两份真实简历不再出现残句、未命名、漏判证据或虚假修改对比。
- 未授权用户不能读取上传文件、他人版本或管理数据。
- AI 出站内容符合隐私页承诺，匿名调用具有可验证的成本边界。
- 桌面与移动端核心流程可完成，生产部署和回滚步骤可直接执行。
